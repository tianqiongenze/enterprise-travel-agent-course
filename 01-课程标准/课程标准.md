# 《企业级旅游智能体项目实战》课程标准

| 项 | 内容 |
|---|---|
| 课程名称 | 企业级旅游智能体项目实战（Enterprise Travel Agent Project Practice） |
| 课程代码 | AI-3X-XX（按各校编码规则） |
| 课程性质 | 专业核心课 / 项目实战课（BKE：Berufsübergreifende Kompetenzen 融入） |
| 总学时 | 64 学时（理论 20 + 实践 44，实践占比 68.75%） |
| 学分 | 4 学分 |
| 适用专业 | 高职高专：人工智能技术应用、大数据技术、软件技术 |
| 开设学期 | 第 4 学期（前导课完成后） |
| 班级规模 | 30~36 人（双元制分组：每组 4~6 人，组内设组长/记录员/汇报员轮换） |

## 一、课程定位

### 1.1 岗位面向

本课程对接**教育部职业教育专业目录**中人工智能技术应用、大数据技术专业的核心岗位群：

| 目标岗位 | 典型工作任务 | 本课程覆盖 |
|---|---|---|
| AI 应用开发工程师（初级） | 智能体服务开发、API 接口实现 | LF2、LF4 |
| 大数据平台运维工程师 | 集群部署、监控、容量规划 | LF1、LF6 |
| 软件测试工程师 | 功能/性能/自动化测试 | LF5 |
| 初级架构助理工程师 | 接口设计、缓存与数据层方案 | LF2、LF3 |

### 1.2 前后接课程

- **前导**：Python 程序设计、数据库技术（MySQL）、Web 前端基础、Linux 操作系统、计算机网络
- **并行**：软件测试技术、云计算基础
- **后续**：顶岗实习、毕业设计（可直接延续本项目的功能扩展课题）

### 1.3 与德国双元制模式的对应

| 德国双元制要素 | 本土化落地 |
|---|---|
| Lernfeld（学习领域）课程方案 | 6 个学习领域替代传统学科章节，每个领域以"企业真实工作任务"驱动 |
| Duales Prinzip（双元：学校+企业） | 学校教室（理论+演练）+ 合作企业机房/真实集群（10.167.2.175/176 生产级 K8s 环境） |
| Ausbilder（企业实训师傅） | 企业工程师担任实训师傅，按《企业师傅评价表》参与考核（占 30%） |
| Lernfeldkonzept 与 Handlungsorientierung（行动导向） | 每次课执行完整六步法：资讯→计划→决策→实施→检查→评价 |
| Arbeitsauftrag（任务书） | 每学习领域发一份《学生任务书》，明确任务、成果物、评分标准 |
| Abschlussprüfung（结业考试） | 期末项目答辩（企业师傅参与评审）替代传统笔试 |

## 二、课程目标

### 2.1 知识目标（布鲁姆：记忆/理解）

K1 说出微服务架构的核心组件与本项目 6 个服务的职责分工（记忆）
K2 解释 REST、GraphQL、gRPC 三种接口风格的适用场景与本项目选型依据（理解）
K3 阐述读写分离、多级缓存（L1 进程内/L2 Redis/L3 向量语义）的工作原理（理解）
K4 说明令牌桶限流的数学模型与 Lua 原子实现要点（理解）
K5 描述异步削峰队列（本地/Pulsar 双后端）的架构位置与消息流转（理解）
K6 陈述 K8s 核心对象（Deployment/Service/HPA/ConfigMap）的作用（记忆）

### 2.2 能力目标（布鲁姆：应用/分析）

A1 能在真实 K8s 集群上完成服务部署、扩缩容与健康检查（应用）
A2 能编写并执行 REST/GraphQL 接口的功能测试用例（应用）
A3 能运用 pytest/BDD 编写自动化测试并用例全覆盖（应用）
A4 能使用 K6 与 Locust 设计压测方案、执行压测并解读 P95/P99 指标（应用/分析）
A5 能根据压测数据分析系统瓶颈并提出扩容方案（分析）
A6 能对照真实监控指标（QPS、缓存命中率、限流拒绝数）定位异常（分析）

### 2.3 素质目标（布鲁姆：评价/创造 + 职业素养）

S1 能对技术方案进行利弊评价并清晰陈述决策理由（评价）
S2 能运用费曼学习法向同伴讲清一个复杂技术概念（创造/表达）
S3 养成"文档先行、证据说话"的工程习惯（所有结论必须有实测数据支撑）
S4 具备德式工程规范意识：任务书、检查单、评审记录完整留痕
S5 团队协作与轮岗意识（组长/记录员/汇报员角色轮换）
S6 课程思政：文旅行业数字化服务民生的职业价值认同；数据安全与用户隐私红线

## 五、考核方案

| 考核模块 | 占比 | 考核者 | 依据 |
|---|---|---|---|
| 过程考核 | 40% | 学校教师 | 六次学习领域成果物质量（07-考核评价/过程考核表） |
| 企业实践考核 | 30% | 企业实训师傅 | 出勤、任务完成度、职业素养（07-考核评价/企业师傅评价表） |
| 期末项目答辩 | 30% | 教师+企业师傅+组间互评 | 答辩评分表（技术 50%+表达 30%+费曼讲解 20%） |

**费曼学习法融入**：每次课设"3 分钟费曼时刻"——学生随机抽取，用大白话向同伴讲清本次课一个核心概念（不使用术语卡壳即重讲），计入过程考核素质分。期末答辩设"费曼环节"：向非技术评委（模拟文旅客户）讲清系统价值。

**补考与重修**：过程考核不合格者可补交成果物；答辩不合格者下一学期随下一年级答辩。

## 六、实施条件

- **师资**：专任教师 1 名（具备企业项目经历）+ 企业实训师傅 1 名（企业工程师）
- **实训环境**：学校机房（浏览器即可访问集群 NodePort 入口）+ 企业真实 K8s 集群（TiDB 8.5/Redis 8/Pulsar/Milvus 2.6/Prometheus，详见 08-参考资料/集群环境速查）
- **教材与资源**：本课程包（标准/计划/方案/教案/PPT/任务书/Lab）+ 主项目仓库 enterprise-travel-agent + 局域网人工测试指南
- **安全要求**：企业集群操作遵循最小权限原则；禁止在生产命名空间执行破坏性命令；压测前须报备
