# 《企业级旅游智能体项目实战》教学实施方案

> 本方案回答三个问题：**怎么教**（双元制本土化设计）、**怎么学**（费曼学习法落地）、**怎么确保学会**（布鲁姆认知分层与证据链考核）。

## 一、德国双元制教育模式本土化设计

### 1.1 双元制核心理念的三个转化

| 德国原模式 | 本土化转化 | 本课程落地 |
|---|---|---|
| Dualität: Betrieb + Berufsschule（企业+职业学校两个学习地点） | 合作企业机房 = 第二课堂 | 每周 4 学时中 2 学时在企业真实集群环境（10.167.2.175/176），学生以"准员工"身份操作生产级基础设施 |
| Lernfeldkonzept（学习领域方案，KMK 1996） | 以岗位工作任务重构知识体系 | 6 个学习领域取代"Java 课/数据库课"的学科逻辑，每个领域是一项完整的企业工作任务 |
| Handlungsorientierung（行动导向教学） | 完整行动循环 | 每次课严格走六步法：资讯→计划→决策→实施→检查→评价，学生是行动主体，教师是咨询者 |
| Ausbilderrapport（企业实训日志） | 双元学习档案 | 学生每周填写《双元学习周志》：学校学了什么、企业做了什么、两者的连接点 |
| Prüfungsordnung（考试条例） | 证据链考核 | 所有成绩必须对应可检查的成果物（报告/截图/代码/答辩录像），杜绝"印象分" |

### 1.2 三个学习地点与资源

| 学习地点 | 环境 | 学生角色 | 典型活动 |
|---|---|---|---|
| 学校教室/机房 | 浏览器 + 局域网 | 学习者 | 六步法演练、GraphiQL 实操、测试编写 |
| 企业机房 | 真实 K8s 集群 SSH/NodePort | 准员工 | 部署观察、压测执行、故障复盘、师傅带教 |
| 线上（GitHub 课程仓库 + 主项目仓库） | 文档/代码/报告 | 社区成员 | 提交成果物、阅读项目同步资料、Issue 提问 |

### 1.3 双导师协作机制

| 角色 | 职责 | 协作节点 |
|---|---|---|
| 学校教师 | 理论精讲、六步法主持、过程考核 | 每周课；第 5/7/10/13/14 周随堂进企业 |
| 企业实训师傅 | 真实环境带教、职业规范示范、企业考核 | 【企】课次主持实施与检查环节；期末答辩评审 |
| 双周教研 | 教学进度对齐、学生问题会商 | 每两周一次 30 分钟线上会 |

### 1.4 本土化的四个"必须"

1. **必须有真实载体**：不做玩具项目——所有教学数据（252 req/s、P95 262ms、31,793 请求 0 失败）来自真实集群实测，学生可亲手复现。
2. **必须有德式规范**：任务书-检查单-评审表三件套贯穿；文件命名、文档结构参照 DIN 式严谨风格。
3. **必须有轮岗**：每组 4~6 人，组长/记录员/汇报员每学习领域轮换一次，覆盖全员核心体验。
4. **必须有中国职教特色**：课程思政融入（文旅数字化服务民生、数据安全红线、工匠精神），对接 1+X 证书（云计算/测试）考点。

## 二、费曼学习法落地设计

### 2.1 四步循环在课堂中的映射

| 费曼步骤 | 课堂载体 | 时间 |
|---|---|---|
| 1. 选定概念 | 每次课"费曼时刻"抽签确定讲解题目（见授课计划最后一列） | 3min/人 |
| 2. 教给外行 | 向同伴用大白话讲解，禁用未解释的术语（用术语卡即重新抽题） | 3min |
| 3. 发现卡壳 | 听众举"红牌"记录卡壳点；讲解者当场回教材补漏 | 即时 |
| 4. 简化类比 | 用生活类比重讲（例：令牌桶=景区售票窗口按固定速度放票） | 2min |

### 2.2 评分与激励

- 费曼时刻计入过程考核素质分（每次 0~5 分：清晰度 2 + 类比质量 2 + 应对追问 1）
- 期末答辩专设"面向模拟文旅客户"的费曼环节（评委含 1 名非技术教师扮演客户），占答辩 20%
- 学期"金牌讲解员"评选：累计得分最高 3 名，颁发证书（企业师傅署名）

### 2.3 教师操作要点

- 抽签用随机名单工具，杜绝回避；每次课 3 人，一学期覆盖全班 1.5 轮
- 卡壳不是扣分项而是得分机会——当场补漏并重讲成功可得满分
- 建立班级"类比库"：好类比记入课程仓库 08-参考资料/优秀类比集（学期末更新）

## 三、布鲁姆认知模型的分层落地

### 3.1 六层级在教学中的对应

| 布鲁姆层级 | 本课程载体 | 考核证据 |
|---|---|---|
| 记忆 Remember | 课前 5 分钟"架构速答"（6 服务名/端口/职责） | 速答记录 |
| 理解 Understand | 费曼时刻；概念图作业 | 讲解量表 |
| 应用 Apply | Lab 实操（GraphiQL/压测/部署） | Lab 成果物 |
| 分析 Analyze | 瓶颈定位（200VU 为何变慢）、契约差异分析 | 分析报告 |
| 评价 Evaluate | 方案决策会（学生投票并陈述理由） | 决策记录 |
| 创造 Create | 期末扩容清单设计、答辩方案 | 答辩成果 |

### 3.2 认知爬坡原则

每次课的六步法严格沿"记忆→理解→应用"爬坡，每个学习领域的成果物要求至少达到"分析"层级，学习领域结束时的综合任务达到"评价/创造"层级。**禁止把"应用"层任务出成"记忆"层考试题**。

### 3.3 差异化教学

- 基础薄弱学生：提供"脚手架检查单"（每步给具体命令），先达成"应用"层
- 学有余力学生：领取"挑战包"（例：给 GraphQL 增加新字段并补三面契约测试），冲击"创造"层
- 期末答辩允许"基础档"与"挑战档"两套评分基准，分别评优
