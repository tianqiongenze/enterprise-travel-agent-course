# 第 5 次课教案：gRPC 与三面契约一致性

| 项 | 内容 |
|---|---|
| 周次 | 第 5 周 |
| 学习领域 | LF2 接口设计与微服务（3-5 周） |
| 学时 | 4 学时（180 分钟） |
| 场所 | 【企】合作企业机房（真实集群） |
| 教学方法 | 双元制六步法 + 费曼时刻 + 布鲁姆分层 |

## 一、教学目标（布鲁姆分层）

- **[记忆]** 说出 3 个 proto 文件、4 个 rpc 方法 —— Remember：能够回忆与陈述
- **[分析]** 对照 proto/GraphQL/OpenAPI 找出字段差异 —— Analyze：能够拆解与归因
- **[评价]** 评价三面契约一致性的工程价值 —— Evaluate：能够依据标准评判

## 二、重点与难点

- **重点**：policy/ranker/runtime 三份 proto；common.proto 共享消息；契约核对方法
- **难点**：proto 的强类型与 GraphQL SDL 的对应关系

## 三、教学过程设计（双元制六步法，180 分钟）

| 步骤 | 德语 | 时长 | 活动设计 |
|---|---|---|---|
| 资讯 | Informieren | 30min | gRPC 二进制协议与 JSON 对比；ranker 双栈（HTTP+gRPC）设计 |
| 计划 | Planen | 20min | 分工：每组认领一份 proto 做字段映射表 |
| 决策 | Entscheiden | 15min | 核对表模板确认（字段/类型/缺失项/结论） |
| 实施 | Durchführen | 70min | 读仓库 data-contracts 实际文件→填核对表→调 ranker 直连接口对照 |
| 检查 | Kontrollieren | 30min | 交叉核对他组核对表；师傅抽查 |
| 评价 | Bewerten | 15min | 费曼×3 + 师傅总结契约治理 |

## 四、费曼学习法环节

- **费曼题目**：讲清：为什么一个功能要做三种接口（各给一个适用场景）
- **规则**：抽签 3 人 × 3 分钟；禁用未解释术语（听众举红牌即重讲）；当场补漏成功得满分
- **评分**：清晰度 2 分 + 类比质量 2 分 + 应对追问 1 分（计入过程考核素质分）

## 五、布鲁姆达成检验（随堂快测）

- **Q：ranker 的两个打分 rpc 是什么？**
  - A：ScoreHotel / ScoreTransport（含 batch 版本）
- **Q：三面契约是哪三面？**
  - A：gRPC proto / GraphQL SDL / OpenAPI(REST)
- **Q：common.proto 里有什么？**
  - A：共享消息定义（不含 service）
